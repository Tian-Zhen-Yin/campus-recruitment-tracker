# 台账只说用户语言，工程语言只属于控制台

台账是求职者的界面，控制台是本机的引擎机房。我们决定：台账界面（文案、按钮、状态、错误提示）只使用用户语言——公司、投递、进展、接入、拍板；「状态包、引擎、抓包、接口、授权、轮询」等工程词汇只允许出现在控制台（/console/）与帮助文档中。数据主权永远在浏览器本地，控制台抓到的官网数据只是可丢弃的缓存。机制对用户不可见，行为对用户可预期：接入的公司自动更新，拿不准的进展请求拍板，一切改动有快照可回滚。

## Considered Options

- **界面保留机制词以换取「透明」**：被否——目标用户是非技术求职者，机制词带来的是理解负担而非透明；透明由「可预期 + 可回滚」提供。
- **全自动改写 + 事后回滚（不问用户）**：被否——官网偶发脏数据会静默改写用户数据，毁掉信任；拍板是信任边界，只发生在用户主动打开的场景。
- **文件桥接（选择状态包文件）作为并列模式**：被否下线——它服务的场景（本机控制台在跑、浏览器却无法直连）在现实中不存在；直连不可达时只显示引导，不再提供文件工作流。
